# Architecture

Technical architecture of the Aegis theme and its relationship to the framework and companion plugins.

## Four-Layer Model

| Layer | Location | Responsibility |
|-------|----------|----------------|
| **Theme** | `wp-content/themes/aegis` | FSE templates, generic theme patterns (excluding WC/TI block patterns), theme blocks, thin PHP glue |
| **Framework** | `vendor/aegis/framework` | Core block enhancements, variations, design system engine, injection hook firing |
| **Free plugin** | `wp-content/plugins/aegis` | Admin, map/modal, snippets, conditionals, integrations, analytics, **WooCommerce/TI Wishlist block patterns** (gated) |
| **Pro plugin** | `wp-content/plugins/aegis-pro` | Hook pattern CPT, video stack, query pro, license, Pro patterns |

## Template gating

FSE **templates** remain in the theme (`templates/` + `theme.json`). WooCommerce and wishlist templates are **hidden from the Site Editor template picker** when dependencies are inactive via `vendor/aegis/framework/src/DesignSystem/Templates.php` (`get_block_templates` filter). See [Template Reference](../reference/template-reference.md).

## Theme Overview

- **PSR-4 autoloading** via Composer — namespace `Aegis\` mapped to `src/` (theme glue + blocks)
- **Framework bootstrap** — `Aegis::register()` from `vendor/aegis/framework`
- **Theme services** — `CompanionNotice`, `GitHubUpdater`, `BlockRegistrar` (theme blocks from `blocks-manifest.php`, Related Posts and Slider extras localization, Related Posts pattern gating), `NavigationFallback`, and `PatternDependencies` (hides patterns whose blocks need an inactive plugin, and strips them from headers, when the editor loads patterns), all started in `src/bootstrap.php`

## Namespace Structure (`src/`)

```
src/
├── bootstrap.php              # Composer files autoload — starts the theme services below
├── helpers.php                # Pattern URL helpers (required from functions.php)
├── NavigationFallback.php     # block_core_navigation_render_fallback: sample menu instead of every page
├── PatternDependencies.php    # rest_pre_dispatch (patterns endpoint): hide patterns with blocks from inactive plugins
├── Admin/
│   ├── CompanionNotice.php    # Install companion plugin notice (GitHub release zip)
│   └── GitHubUpdater.php      # update_themes_github.com: updates from GitHub releases
└── Blocks/                    # block.json + TSX sources (compiled in place)
    ├── BlockRegistrar.php
    ├── RelatedPostsQuery.php
    ├── ToggleId.php           # Stable data-toggle-id for Toggle
    └── blocks-manifest.php    # Generated by npm run build
```

## Framework (`vendor/aegis/framework`)

Registered via `ServiceProvider` when `Aegis::register()` runs:

- 37+ core block render filters (`CoreBlocks\`), including `core/icon` and Lightbox extras
- Icon library registration (`Icons\Library`) on WordPress 7.1+; `wp aegis migrate-icons` for leftover Image icons
- Block settings (Visibility, Animation, Query enhancements, …). Visibility viewport/a11y extras add CSS classes to the block or post-content root; hook patterns wrap. Color Scheme follows `is-style-*` and `default-mode-*` on `body`.
- Block variations (Accordion, Counter, Marquee, Newsletter, SVG Image — not Image Icon). Marquee extras are gated at **Aegis → Blocks → Marquee**. Accordion, Newsletter, and SVG styles register once in PHP (`register_style()`), not via `BlockStyles`. The SVG inspector is `svg-editor.js` (no SVGOMG Optimize control).
- Design system (Patterns scanner, REST trim, template pattern expander, dynamic template parts, DarkMode, SkipLink, BlockStyles for decorative styles such as surface/checklist, EditorAssets, navigation overlay, editor overlay fix)
- Integration CSS (gated by plugin settings when the plugin is active), including Meta Box form styling (`plugins/meta-box.css`), Easy Digital Downloads download/checkout styling (`plugins/edd/edd.css`), AffiliateWP Affiliate Area and login/register form styling (`plugins/affiliate-wp.css`), Fluent Forms form element and button styling (`plugins/fluent-forms.css`, injected on `fluentform` / `ff_form` / `fluent_form` / `fluent-form` / `ff-form`), Fluent Booking calendar and appointment styling (`plugins/fluentbooking.css`, injected on `fluent-booking` / `fcal_` / `fcal-` / `fluentbooking`), Gravity Forms form element, input, and button styling (`plugins/gravity-forms.css`, injected on `gform_wrapper` / `gravity-theme` / `gform` / `gform_body` / `gform-body` / `gfield`), WooCommerce shop/cart/checkout styling (`plugins/woocommerce/woocommerce.css`) and breadcrumbs (`plugins/woocommerce/woocommerce-breadcrumbs.css`, injected on `woocommerce-breadcrumb` / `wc-block-breadcrumbs` / `wp-block-woocommerce-breadcrumbs`). Classic and Store Breadcrumb delimiters wrap in `.aegis-breadcrumb-separator` (`woocommerce_breadcrumb_defaults` and `render_block_woocommerce/breadcrumbs`). Also the Code Block Pro overlay (`plugins/code-block-pro.css`), and the Syntax Highlighting Code Block overlay (`plugins/syntax-highlighting-code-block.css`, injected on `hljs` / `shcb-`)
- Injection hook firing on template parts and post content

## Bootstrap Flow

### 1. functions.php

Loads Composer autoload, helpers, textdomain, and `Aegis::register()`.

### 2. src/bootstrap.php

Initializes `CompanionNotice`, `GitHubUpdater`, `BlockRegistrar`, `NavigationFallback`, and `PatternDependencies`. Registers the `payment`, `payment-brand`, and `integrations` icon sets and adds `style.css` as an editor style.

### 3. Aegis::register()

Boots the framework ServiceProvider (design system, core blocks, integrations).
